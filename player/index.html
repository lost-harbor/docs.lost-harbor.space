Player guide

Lost Harbor is a typed MUD with a browser interface. You control a character through commands. The room panel, map, chart, comms and windows show the results.

§Start playing

Open the development game for the newest validated build. The production game follows stable releases.

Use the sign-in screen to enter the game and create a character. Choose a name, class and portrait. New characters wake in a private copy of the Meridian Works. The opening teaches the commands through work orders and exploration.

The showcase pilot skips the opening and starts at a ship’s helm. Use that template to try ships and the shipyard. It is a development shortcut, not the normal opening.

The sign-in flow is a development feature. It does not establish a production account-security model.

§Read the screen

  • The top ribbon identifies your character and current situation.
  • The room panel lists exits, people and objects.
  • The map shows rooms. At the helm, the system chart shows space.
  • The centre transcript holds command output.
  • The social column shows comms, jobs, group and crew.
  • Windows hold details such as your character sheet, inventory and ship.

Click an entity to see its available actions and exact commands. Type the same command when you prefer the keyboard. Character creation uses the sign-in forms rather than a game command.

§First commands

Type a line in the command input and press Enter. Allow queued actions to finish before sending a long sequence.

CommandResult
lookRead the room again.
examine railInspect a named object.
helpList engine commands by group.
help movementRead help for a command group.
help getRead a command’s syntax.
north, south, east, west, up, downTake an exit.
inventoryList carried items.
scoreRead your character’s state.
jobsRead available and active work.
stopStop queued actions.

Use the exit names printed by look. Some exits have names such as lifeboat instead of compass directions. An error explains a missing target, blocked route or unmet condition. Read it before repeating the command.

§Items, shops and conversations

get tag
drop tag
give chit to cook
ask hesk about quota
list
buy gloves
wear suit
equipment
use spanner on valve

get takes one matching item unless you request a collection. get all corpse retrieves the contents of a corpse. wear equips suitable gear. remove takes equipped gear off. Inspect an object to find its uses.

Shops list offers through list. Conversation topics and work orders provide context for ask. accept <number> accepts an available job. Some jobs complete on an action. Others use deliver.

§Combat and recovery

Use consider <target> before attacking. kill <target> starts or continues an attack. Skills have their own commands, such as use snap-shot drone. Read skills and help for your character’s options.

Use healing items before your hit points run out. The opening includes a scripted death and clone recovery. Death can leave equipment on a corpse, so return and inspect the scene. The walkthrough explains the opening’s recovery route.

A suit protects against the opening’s vacuum. Wear it before crossing the outer surface.

§Your first ship

At the helm, type pilot to enter piloting mode. Type ship for status and window ship for the ship window. The opening’s lifeboat requires repairs before launch.

pilot
launch
fly spindle
dock
refuel
launch
fly gate
jump

These are separate steps, not an instant command sequence. Wait for each flight to arrive before docking or jumping. Watch the chart and read the transcript for progress and failures.

scan reveals contacts. fleet lists owned ships. At a shipyard, shipyard lists offers. Use help <command> before buying, selling or ordering crew. Fuel, location, ownership and available berths constrain ship actions.

§Browser controls

Some commands change only the browser interface. Engine help does not list these local commands.

CommandResult
window characterOpen the character sheet.
window inventoryOpen inventory.
window chartOpen the system chart.
window settingsOpen settings.
map deck, map systemChoose the map card’s view.
chart fitFit the chart to its contents.
filter allShow all transcript categories.
clearClear the visible transcript.

Clearing the transcript does not reset the game. The interface targets desktop viewports of 1920x960 and 1600x860. Touch input and smaller layouts are not established interfaces yet.

§Saves and hosting modes

The public Pages sites run the engine in a Web Worker. They store saves in this browser’s IndexedDB. No multiplayer game server runs on those sites.

Saves belong to the site’s origin and browser profile. Development and production have separate saves. Changing browsers or devices does not transfer a save. Clearing site data removes local saves. Private browsing can discard them when the session ends.

A native development server keeps its own storage. Adding ?local=1 to its URL runs the browser engine instead. That is a different save from the native server’s database.
