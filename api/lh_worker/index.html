Crate lh_worker 

Expand description

The Lost Harbor engine inside a dedicated Web Worker.

web/worker.js is a module worker. It loads this crate’s --target web build and calls open_host. That function opens IndexedDB (lost-harbor and records, keyed kind/key), loads the saved records, and starts an engine with one session. The shim then forwards JSON ClientMsg strings to WorkerHost::handle and calls WorkerHost::tick on an interval. Output goes back as JSON ServerMsg strings. Dirty records go to IndexedDB.

Builder edits are records of kind content. IndexedDB keeps them as an overlay on the content built into the binary, and the engine applies them at boot. plan decides what each save does to the overlay. It is plain Rust, so native tests cover it without a browser.

This crate is the browser twin of lh_server. Both hosts wrap the same lh_engine::Engine. Only the storage and the transport differ.

Functions§

open_host
Opens storage, loads records and builds the engine. Falls back to memory-only play when IndexedDB cannot open.
plan
Turns dirty records into IndexedDB changes, keeping the content overlay small. Content records that match embedded are not needed, so they become deletions. This covers a deleted record that was never in the embedded content, and an edit that was undone. A deletion of an embedded record stays as a stored tombstone, so the record stays deleted after a reload. Other records pass through unchanged.
record_key
IndexedDB key for a record. This is the same kind/key id that lh_store uses.
