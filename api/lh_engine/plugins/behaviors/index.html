Module behaviors 

Expand description

NPC behaviors: data-driven triggers, conditions, and actions. NPC behaviors: data-driven reactions, a modern take on CircleMUD’s special procedures and DG script triggers.

A behavior is a content record (lh_content::Behavior) with a list of rules. Each rule has a trigger, conditions, and actions. An NPC lists the behaviors it uses by id, so many NPCs can share one. Builders edit the rules as structured data in the builder, never as script text.

This plugin is the runtime. It turns game events into triggers and runs the matching rules:

TriggerSource in the game
EnterArrived, when a player walks into the NPC’s room
SpeechSpoke, when a player says a keyword in the NPC’s room
AskedAsked, raised by ask <npc> about <topic>
Giventhe give command, when the item goes to this NPC
Commandan unknown verb typed in the NPC’s room
Timerevery secs seconds while a player is in the room
Clockwhen the station clock reaches the time
Calledthe Run action of another rule

A rule runs its then actions when every condition holds. Otherwise it runs its otherwise actions. Conditions and actions about “the actor” use the player who caused the trigger. Timer and Clock rules have no actor, so actor conditions fail and actor actions do nothing.

This plugin registers:

  • Content kind: behavior, with an apply step that resets its timers.
  • Component: Flags, the named flags a player has, saved under flags.
  • Resource: BehaviorClock, the timer and clock bookkeeping.
  • Observers: Arrived, Spoke, and Asked.
  • Command: give, hidden, at priority 4. It sits between the jobs plugin’s give (5) and the ordinary give (0).
  • Fallback: command_fallback, for Command triggers.
  • System: tick_behaviors in Stage::Update, for Timer and Clock.

Independence: besides core modules, it reads clock::Clock for the time, jobs::Jobs for job conditions, and items::match_items to read the item word in give. Job actions go through the StartJob and AdvanceJob events, so it never calls the jobs plugin.

Functions§

holds_all
True when every condition holds for actor, with no NPC involved. Other plugins use it for exit guards and job gates. Conditions about the actor read the actor, and a Day condition reads the actor’s room.
