Plugin architecture.

Every feature is a Plugin. A plugin registers what it contributes on an AppBuilder: commands, client-message handlers, views, event observers, tick systems, persistence sections, builder content kinds and so on. The engine core only knows the registries, never the features.

Adding a feature means adding a plugin. No other system needs to change. This is the Open/Closed principle: the core is closed for edits and open for extension.

Several registries are chains of responsibility. Command handlers can return Outcome::Pass to let the next handler with the same name try. Movers claim the moves they understand. Views with a higher priority override lower ones. For example, piloting replaces the room and map views while you hold the helm.

Rust note: Registries holds plain lists of function pointers (fn). A function pointer is a value that points at a function with a fixed signature. Plugins pass named functions, not closures, so the lists stay simple and Send + Sync.
