Module edits 

Expand description

Builder edits to the content, kept as an overlay on the content files.

The content files are the source of truth. A builder edit changes the live content at once and also lands in ContentEdits. The building plugin turns each edit into a content record, so the host saves it. The server writes it back to the content files. The browser worker keeps it in IndexedDB and replays it at the next start.

The overlay matters when the content reloads. A reload reads the files again, and an edit that the host has not written yet is not in them. So overlay puts every pending edit back on top of fresh content. Once the server has written the files, it calls Engine::forget_content_edits, and the overlay empties.

A content record has the key <kind>/<id>, for example room/spindle:concourse. Its JSON is the record’s data, or null for a deleted record. A deletion is a normal record (a tombstone), not a removed one. That way the worker can store “this file record is gone” in IndexedDB.
