Module queue 

Expand description

The action queue and the timers that drive it. The action queue: every actor (player, simulated player, NPC) runs typed commands through the same pipeline. Commands run in order. A busy command (walking a long tube, searching, resting) holds the queue until it completes. stop clears it immediately.

The pipeline has four steps:

  1. submit splits the line on ; and adds each part to the queue.
  2. pump pops the next part and runs it with execute.
  3. settle runs the result. A quick command finishes now. A busy one becomes the running action.
  4. tick_queues finishes busy actions when their time is up, then pumps again.
