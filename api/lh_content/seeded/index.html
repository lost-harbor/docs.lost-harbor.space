Module seeded 

Expand description

Phrase slots in record text, written with a seed from the record id. Phrase slots inside record text, written once per record.

An item, NPC or room can use phrase slots in its text, for example an item named <house:name> sidearm with the keyword <house:name>. The slots are written with a seed made from the record’s kind and id, so the text is the same on every load, on every host, for every player. Every field of one record starts from that same seed, so the first slot of the name and the first slot of the look text write the same word when they name the same phrase.

Record text names phrases, never chains. A chain is an ingredient. A phrase is the tag that the world uses. So a slot such as <chain:house:name> in an item name is a problem that the validator reports, and the text stays raw. This keeps every tag in one place: a builder who changes a phrase changes every record that uses it.

Each record also has a roll number, 0 by default. A builder who wants other text for the same record raises the roll. The seed then changes, the id stays, and no reference to the record breaks.

The content files keep the slots. shown makes a copy of the content with the slots written out, and the game shows that copy. The builder edits the copy with the slots, so a save never loses them.

The written fields:

  • item: name, plural, keywords, line, look;
  • NPC: name, short, line, keywords, look, say_name;
  • room: name, description.

A keyword with a slot can write more than one word. Each word becomes its own keyword, in lower case.

Pattern: visitor. One function per kind visits each text field, and the same visit serves both writing and checking.

chain_refs
The chain ids that a record text names directly, in order.
fields
The text that players see for each field of one record that holds slots, by field name. List fields such as keywords join their entries with “, “. Fields with no slots are left out, so the map is empty for most records. The builder shows it beside the raw text.
problems
The slot problems in one record’s text, as (field, problem) pairs.
record_seed
The seed of one record at one roll. Roll 0 is seed_of itself, so records made before rolls existed keep their text.
seed_of
The seed of one record: the FNV-1a hash of kind:id.
shown
A copy of the content with every slot in record text written out. A field whose slots fail stays as it is. The validator reports it.
tag_users
Every record that names id in a slot, as (kind, id) pairs.
write
The text with its slots written from seed. Ok(None) when the text has no slots.
write_record
Record text with its slots written, like write(), but a slot that names a chain is an error. Records reference phrases, not chains.
